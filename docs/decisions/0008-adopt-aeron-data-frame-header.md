# 0008. Adopt Aeron's data frame header, field for field, as version 0

- **Status:** Accepted
- **Date:** 2026-10-11
- **Invariants affected:** 1, 2, 3, 6
- **Supersedes:** none

## Context

The first feature of the first slice (ADR 0007) is the data frame header: the 32
bytes in front of every fragment, on the wire and in a log buffer. It is the first
wire layout, so it sets the conventions `spec/` follows, and it is read once per
message on the data plane, so it must be readable in place with no copy, no
allocation and no panic path (invariant 2). Mixed versions run during an upgrade
(invariant 3), so the header carries a version. `CLAUDE.md` says to copy Aeron's
behaviour and names where they are good, and Aeron's header has carried production
traffic since 2014.

Aeron's layout, read on 2026-10-11 from `aeron_udp_protocol.h`,
`HeaderFlyweight.java` and `DataHeaderFlyweight.java` on its `master` branch and from
its wiki: frame length `int32`, version `int8`, flags `uint8`, type `int16`, term
offset, session id, stream id and term id `int32`, reserved value `int64`, packed to
4 bytes, 32 bytes in all, little-endian, frames aligned to 32 bytes, version 0, types
PAD 0 and DATA 1 among others, flags BEGIN `0x80`, END `0x40`, EOS `0x20` and a
newer REVOKED `0x10`.

## Decision

Cavalry's data frame header is Aeron's, field for field, and `spec/frame.md` is its
specification at version 0: the nine fields at Aeron's offsets and widths,
little-endian, 32 bytes, frames at 32-byte-aligned offsets, version 0 meaning this
layout, types 0 (padding) and 1 (data) specified now and every other type with its
own frame later, flags BEGIN, END and EOS at Aeron's bits with the five low bits
reserved, written as 0 and ignored by a reader so that a later version can use them.
A reader runs four checks in a fixed order, too short, version, type, length, and
reports the first that fails by name, so that every implementation says the same
thing about the same bytes; each rejection increments a counter once the counters
file exists. Cavalry does not promise to interoperate with Aeron: the layout is
copied, the specification is Cavalry's own, and it changes only through an ADR and a
version bump. The vectors in `spec/vectors/frame.json` are written by
`spec/vectors/frame.py`, a reference encoder in the Python standard library that is
independent of the Rust code. A test in `cavalry-proto` runs every vector on every
`just test`, and `just conformance` runs that test alone until a client exists. The
parser is fuzzed two ways: a no-panic test over generated bytes in `just test`, and a
`cargo fuzz` target run by `just fuzz` on nightly, outside CI like `just miri`.
`docs/reference/frame.md` includes the spec page into the book unchanged.

## Alternatives considered

- **A layout of Cavalry's own.** Lost: nothing in Aeron's header is wrong for
  Cavalry today, its names are already Cavalry's by rule, and a layout of our own
  would have to be explained from scratch where Aeron's documentation already
  explains this one.
- **A 64-byte header with room to grow.** Lost: it doubles the header's share of a
  small message, and the version byte is the room to grow.
- **A self-describing header, such as SBE.** Lost: a codec in the per-message path
  for a layout that never varies.
- **Big-endian, as network order.** Lost: every target Cavalry runs on is
  little-endian, and Aeron chose little-endian for that reason.
- **Rejecting a frame with reserved flag bits set.** Lost: a reader of version 0
  would then refuse frames from a later writer that uses a reserved bit, which
  breaks the mixed-version rule (invariant 3). Ignoring them costs nothing.
- **Adopting REVOKED now.** Lost: it belongs to publication revocation, which has no
  specification yet; its bit stays reserved and can take that meaning in a later
  version.
- **Interoperability with Aeron as a goal.** Lost: it would bind every later wire
  decision to Aeron's. Copying the layout costs nothing and promises nothing.
- **Checking the four rejections in any order.** Lost: two implementations would
  report different reasons for the same bytes, and the conformance vectors could
  not pin one.
- **Hand-computed vectors.** Lost: a hex string typed by hand is checked by nothing.
  A reference encoder in another language checks the Rust code, and the Rust code
  checks it.
- **Fuzzing only in CI, or only outside it.** Lost on both sides: nightly and
  `cargo fuzz` on every CI run cost minutes for a parser whose input space a
  generated-bytes test covers on every commit, while a target nobody runs finds
  nothing. Both exist; CI runs the cheap one.

## Evidence

- Aeron's `aeron_udp_protocol.h` (`#pragma pack(4)`, `aeron_frame_header_t`,
  `aeron_data_header_t`, `AERON_FRAME_ALIGNMENT 32`, `AERON_FRAME_HEADER_VERSION 0`,
  the `AERON_HDR_TYPE_*` and `AERON_DATA_HEADER_*_FLAG` values), `HeaderFlyweight.java`
  and `DataHeaderFlyweight.java` (field offsets 0, 4, 5, 6, 8, 12, 16, 20, 24,
  `HEADER_LENGTH 32`, `LITTLE_ENDIAN` on every multi-byte access), and the wiki's
  Transport Protocol Specification ("Data Frame", "Padding Frames", "Design
  Assumptions"), all read on 2026-10-11.
- `spec/vectors/frame.py` produced 18 vectors on 2026-10-11: eight valid, eight
  invalid, two that pin the order of the checks.
- Nothing measured: a fixed 32-byte layout read in place has no alternative to
  measure against until `just bench` exists (ADR 0007).

## Consequences

Easier: Aeron's documentation and tools explain and dump Cavalry's frames; every
later frame type keeps the first eight bytes, so one reader dispatches on type; a
client in any language can be checked against the same vectors.

Harder: frame length is at most 2^31 − 1 and its sign bit belongs to the log buffer's
claim protocol, which the log buffer spec must honour; a change to any field is a
new version and a new ADR; `cargo fuzz` needs a nightly toolchain on the laptop that
runs it.

Revisit: when a field has to change, with version 1 and a superseding ADR; when
publication revocation is specified, for the `0x10` bit; when CI gets a nightly
toolchain for another reason, to move `just fuzz` into it.
